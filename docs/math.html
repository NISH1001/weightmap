Companion to the Weightmap Notebook · every formula used in the experiments, with a tiny worked example and our real numbers

The maths, step by step

Each section follows the same pattern. First the idea in one sentence, then the formula, then a toy example small enough to check by hand, then what it meant in our runs. The toy numbers on this page are computed live in your browser, so you can change the sliders and watch the formulas move.

0Vectors, matrices and shapes: what the numbers actually are

Everything in this project is a table of numbers. If you know what each table's rows and columns mean, every formula later is just "multiply these tables". This section builds that picture with a real sentence and real numbers from the models.

0.1 · What is d?

d is how many numbers the model uses to describe one token. It is fixed when the model is designed, the same for every token and every layer. People call it the hidden size or residual width.

Modeld (numbers per token)layers (blocks)MLP neurons per block
SmolLM2-135M (tiny / small S)576301,536
Qwen2.5-0.5B (small S)896244,864
Qwen2.5-1.5B (large L)1,536288,960

Think of it as a spreadsheet row with d columns. Qwen-0.5B describes every token with a row of 896 numbers; Qwen-1.5B uses a wider row of 1,536. A bigger d means more room to store information about the token and its context.

Name clash

Later, d also names the loop direction (section 8). That's a different thing: a vector with d entries. When it matters we write "width d" vs "direction d".

0.2 · What are h₁, h₂, …, h_d?

A token's state is the row h = [h₁, h₂, …, h_d]. Each hᵢ is one number, the i-th coordinate. For Qwen-0.5B, h₁ is column 1 of 896, h₂ is column 2, and so on up to h₈₉₆.

The coordinates have no individual names. There is no "h₄₇ = is a noun". Meaning is spread across many coordinates at once, and what matters is the direction the whole row points. Colour is a good analogy. A colour is 3 numbers (R, G, B). "Orange-ness" isn't any single one of them; it's a particular mix, a direction in RGB space. A model's "this text is looping" is likewise a direction in its 896-number space (section 8).

This is also why two models can't be compared coordinate by coordinate. Qwen-1.5B's coordinate 1 has nothing to do with Qwen-0.5B's coordinate 1. A rotated or shuffled set of coordinates would describe the same model equally well. So we need a map that learns how to translate one row into the other.

0.3 · A real example: "Tom has 3 apples."

The tokenizer splits the sentence into 6 tokens. Each token is a number, its ID in a vocabulary of 151,936 entries (both Qwen models share it):

tokensTom24732␣has702␣220318␣apples40676.13

Layer 0, the embedding. The model owns a giant table of 151,936 rows × 896 columns, one row per vocabulary entry. Step zero is a lookup: token 702 ("␣has") gets row 702. We checked: the model's layer-0 state is exactly that table row.

Layers 1 to 24, the blocks. Each block reads every token's row, computes something (attention looks at earlier tokens; the MLP processes each token), and adds its result to the row. After 9 blocks the row for "␣has" no longer means just "has". It now reflects "has, after Tom, in this sentence".

Three things to notice:

  • Rows grow. Embedding rows are tiny (length ≈ 0.5). By layer 9 they are about 15, because every block keeps adding to them.
  • The first token is a monster. "Tom" has length 1,556, about 100 times the others; in Qwen-1.5B at layer 10 it's 11,637. Models use the first position as a dumping ground (the "attention sink"). That's why every experiment skips position 0 and drops rows longer than 5× the median. One such row would dominate a least-squares fit.
  • Same text, different width. Qwen-1.5B gives each of these 6 tokens a row of 1,536 numbers. At layer 10, "␣has" starts −1.88, 0.08, −0.86, 1.28, … with length 63.5. The two rows are different lengths and use unrelated coordinates, and the map's job is to translate between them.

0.5 · Stacking many texts: the matrices X and Y

To fit a map we need many examples. Take a layer from each model (say Qwen-1.5B layer 10 and Qwen-0.5B layer 9), run both on the same texts, and keep the rows for the same tokens. Stack the rows from all texts on top of each other:

X = L's rows n × 1536 row t = Qwen-1.5B's state for token t Y = S's rows n × 896 row t = Qwen-0.5B's state for the SAME token t n ≈ 12,000 tokens (up to 32 per text, from a few hundred texts) X holds 12,000 × 1,536 ≈ 18.4 million numbers; Y ≈ 10.8 million

Row t of X and row t of Y describe the same token in the same text, seen by two different models. That pairing is the whole dataset. The map learns: "when L's row looks like this, S's row looks like that".

0.6 · The map is a matrix: what multiplying does

The map is a matrix W with 1,536 rows and 896 columns. Multiplying one L row (1 × 1536) by W gives one predicted S row (1 × 896):

Toy version you can check by hand. Pretend L uses 3 numbers per token and S uses 2, with 4 tokens:

X (4 tokens × 3) W (3 × 2) Ŷ = X W (4 × 2) ┌ 1 0 2 ┐ ┌ 0.5 0 ┐ ┌ 1.5 −1 ┐ │ 0 1 1 │ · │ 0 1 │ = │ 0.5 0.5 │ │ 2 1 0 │ └ 0.5 −0.5 ┘ │ 1 1 │ └ 1 1 1 ┘ └ 1 0.5 ┘ entry (token 1, S-coordinate 1) = row 1 of X · column 1 of W = 1×0.5 + 0×0 + 2×0.5 = 1.5 entry (token 1, S-coordinate 2) = 1×0 + 0×1 + 2×(−0.5) = −1

How to read W:

  • Entry W[i, j] says how much L's coordinate i contributes to S's coordinate j.
  • Column j is the recipe for S's coordinate j: "take 0.5 of L's coordinate 1, plus 0.5 of L's coordinate 3". The real W has 896 such recipes, each mixing all 1,536 of L's numbers.
  • Every token uses the same recipes. W has 1,536 × 896 ≈ 1.38 million entries, fitted once from the 12,000 paired rows (section 2), then reused for any new token.

A bias row b (1 × 896) is added to every prediction (ŷ = xW + b). It handles the fact that the two models' rows are centred at different places.

Part 1 · Building the map

1Lining up tokens across tokenizers

Idea. We can only compare two models' states at moments where both have read exactly the same text.

Each tokenizer cuts text differently. For each token we record the character position where it ends. We keep only the positions where both tokenizers end a token at the same character.

In our runs

Qwen-0.5B and Qwen-1.5B share a tokenizer, so every token aligns. Across families (Qwen ↔ SmolLM2) only the shared-boundary positions are used. We take up to 32 aligned positions per text and cap the total at 12,000 tokens to keep memory low. We skip the first token of each text, because every model uses it as a "dump" slot with huge values (the attention sink).

2Ridge regression: fitting the map in one step

Idea. Find the matrix W so that L's state times W is as close as possible to S's state, across thousands of tokens. A small penalty stops W from blowing up.

The 1-number version first

Suppose each state were a single number. We want y ≈ w·x. Least squares picks w to minimise the total squared miss Σ(yᵢ − w xᵢ)². Setting the derivative to zero gives:

plain least squares: w = Σ xᵢyᵢ / Σ xᵢ² ridge (penalty λw²): w = Σ xᵢyᵢ / (Σ xᵢ² + λ) ← λ pulls w toward 0

Toy data: four training points (x, y) = (1, 1.2), (2, 1.9), (3, 3.2), (4, 3.9). Then Σxy = 1.2 + 3.8 + 9.6 + 15.6 = 30.2 and Σx² = 1 + 4 + 9 + 16 = 30, so with λ = 0 the slope is w = 30.2 / 30 ≈ 1.007. Drag λ to see the penalty shrink the slope.

The matrix version

Now each state is a row of numbers. Stack n aligned tokens: X is L's states (n × 1536) and Y is S's states (n × 896). Each column of W is one little regression like the one above, all solved at once:

W* = argmin ‖Y − XW‖² + λ‖W‖² = (XᵀX + λI)⁻¹ XᵀY shapes: XᵀX is 1536×1536, XᵀY is 1536×896, W is 1536×896 mapped state: ŷ = x W + b (b = intercept, from centring X and Y first)

XᵀX is the matrix version of Σx², and XᵀY is the matrix version of Σxy. The λI adds λ along the diagonal, exactly like "+ λ" in the 1-number formula. Solving it is one linear-algebra call, a fraction of a second. No gradient descent and no training loop.

In our runs

λ is picked from {10⁻⁴, 10⁻³, 10⁻², 10⁻¹} by fitting on 80% of the training texts and scoring on the other 20%. The map is then refit on all training texts with that λ.

3R², and why "holdout" must mean whole texts

Idea. R² is the share of the variation in the target that the prediction explains. 1 is perfect; 0 means you might as well predict the average every time.

R² = 1 − Σ (y − ŷ)² / Σ (y − ȳ)² └─ what you miss ─┘ └─ what "always guess the mean" misses ─┘

Toy example. Targets y = [2, 4, 6, 8], predictions ŷ = [3, 4, 5, 8], mean ȳ = 5.

misses: (2−3)² + (4−4)² + (6−5)² + (8−8)² = 1 + 0 + 1 + 0 = 2 mean's misses: (2−5)² + (4−5)² + (6−5)² + (8−5)² = 9 + 1 + 1 + 9 = 20 R² = 1 − 2/20 = 0.90

For vector targets (896 numbers per token) we add up the squared misses over every coordinate of every token, top and bottom. That is a single R² for the whole map.

The leakage trap

Two neighbouring tokens in the same text have very similar states. If you split tokens randomly into train and test, the test set is full of near-copies of training tokens. The score looks great but measures memory, not generalisation. So we split by whole texts: no test token's text was ever seen in fitting.

In our runs

The very first version scored R² = 0.85. Most of that excess came from chat-template tokens, which every text shares and both models encode alike (−0.17); the holdout unit itself cost only 0.02–0.03. On answer text with whole texts held out the figure is about 0.66. Every number in the notebook uses the strict version.

4CKA: which layer of L matches which layer of S?

Idea. Two layers "think alike" if they agree on which tokens are similar to which, even if their coordinates are rotated, stretched or of different widths.

Build each model's token-similarity table K = XXᵀ (entry i,j is the dot product of token i's state with token j's). CKA compares the two tables, after centring each column of X and Y:

CKA(X, Y) = ‖XᵀY‖²_F / ( ‖XᵀX‖_F · ‖YᵀY‖_F ) ‖M‖²_F = sum of squares of all entries equivalently: the cosine similarity between the two similarity tables XXᵀ and YYᵀ

Toy example. Four tokens with 2-number states (already centred). Y₁ is X rotated 90° and stretched 3×, so it is "the same geometry in different coordinates". Y₂ is unrelated.

In our runs

For each S layer we pick the L layer with the highest CKA on 100 texts. The matches come out in depth order (for example, Qwen-0.5B layer 10 ↔ Qwen-1.5B layer 13). Picking the L layer by best held-out R² instead gives the same quality.
Part 2 · Is the map real?

5The token-identity control

Idea. If both models see the word "the", part of each state is predictable just from that fact, without any shared understanding. How much of R² is only that?

We fit the same ridge map from three weaker inputs and compare:

  • L's embedding layer only (layer 0, before any block runs). It knows only "which token is this".
  • An untrained copy of L (same architecture, random weights). It mixes in neighbouring tokens but has learned nothing.
  • S's own embedding layer, as a cross-check.
shared-context part = R²(trained L, best layer) − R²(L's embedding only) Qwen-0.5B layer 9: 0.651 − 0.419 = 0.232 Qwen-0.5B layer 14: 0.641 − 0.346 = 0.295 SmolLM2-135M layer 12: 0.727 − 0.594 = 0.133 SmolLM2-135M layer 17: 0.664 − 0.489 = 0.175

Intuition. Imagine predicting a student's essay from another student's essay on the same prompt. Much of the overlap comes from both quoting the prompt. Only what's left over shows they think alike. Here "quoting the prompt" is the token identity, and about two thirds of the headline R² is that.

Why the untrained copy matters

The untrained L scores 0.28–0.49, which is below the plain embedding. Random layers scramble the token identity a little without adding any meaning. So the trained map's extra 0.13–0.30 is real learned structure: small, but real.

6Composing maps along a chain

Idea. If maps are linear, chaining two of them is one linear map, the product of the matrices. Does a chain lose information at every step?

x₁ W₁₂ = x̂₂, x̂₂ W₂₃ = x̂₃ ⇒ x̂₃ = x₁ (W₁₂ W₂₃) (one combined matrix)

A natural guess: if each step keeps a fraction R² of the variation and the losses are independent, the chain should keep roughly the product. The numbers say otherwise.

chain Qwen-1.5B → Qwen-0.5B → SmolLM2-360M → SmolLM2-135M step R²: 0.645 × 0.647 × 0.730 = 0.305 (guess if losses compound) composed, measured: 0.629 direct map 1.5B→135M: 0.659 → the chain keeps 0.629 / 0.659 ≈ 95%

Intuition. What each step loses is mostly the same material: detail that the smaller model can't represent anyway. Once dropped at the first step it can't be dropped again, so the losses overlap instead of multiplying.

7Spearman correlation and an exact p-value

Idea. Do more capable small models map better? With only 5 models, compare rankings, not raw values, and count exactly how often chance would give a result this strong.

modelbits/bytecapability rankmap R²R² rankd (difference)

ρ = 1 − 6 Σd² / (n(n² − 1)) = 1 − 6·2 / (5·24) = 1 − 12/120 = 0.90

Exact p-value by counting. If capability had nothing to do with map quality, every one of the 5! = 120 orderings of the R² ranks would be equally likely. How many give ρ ≥ 0.9?

  • The perfect order (Σd² = 0, ρ = 1): 1 ordering.
  • One swap of two neighbours (Σd² = 2, ρ = 0.9): positions 1↔2, 2↔3, 3↔4 or 4↔5, so 4 orderings.
one-sided p = 5/120 ≈ 0.042 two-sided p ≈ 0.083

So "ρ = 0.9" sounds strong but is a trend, not proof: with 5 points, about 1 random ordering in 12 looks this good in one direction or the other. A 10-model rerun is written (scripts/atlas_extend.py) but not yet run.

Part 3 · Moving a behaviour

8Directions, transport, cosine and steering

8.1 · A behaviour as a direction

Idea. Average the states of tokens where the model is looping, average the states where it is productive, and subtract. The result points "toward looping".

d = mean(h | looping) − mean(h | productive)

Toy example in 2-D. Looping states (3, 1), (4, 2), (5, 1.5) have mean (4, 1.5). Productive states (1, 2), (2, 3), (0, 2.5) have mean (1, 2.5). So d = (4 − 1, 1.5 − 2.5) = (3, −1), with length ‖d‖ = √10 ≈ 3.16.

8.2 · Carrying a direction through the map (the bias cancels)

The map is ŷ = xW + b. Map both class means and subtract:

(mean_loop · W + b) − (mean_prod · W + b) = (mean_loop − mean_prod) · W = d_L · W ⇒ transported direction d_{L→S} = d_L W (no bias: differences don't need it)

So moving a direction from L to S is a single matrix multiply.

8.3 · Cosine similarity: do two directions agree?

cos(a, b) = a·b / (‖a‖ ‖b‖) 1 = same direction, 0 = unrelated, −1 = opposite toy: a = (3, −1), b = (2.8, −1.4) a·b = 8.4 + 1.4 = 9.8; ‖a‖ = 3.162, ‖b‖ = 3.130 cos = 9.8 / 9.899 = 0.990 (about 8° apart)

In our runs

S's own loop direction and L's direction mapped into S have cosine 0.985, about 10° apart. In the MATH experiment, L's "correct vs wrong" direction mapped into S had cosine 0.85 with S's own. High agreement means the map gives S a direction it could already find by itself.

8.4 · Steering: push every token against the direction

h ← h − s · ‖d_S‖ · d̂ d̂ = d / ‖d‖ (unit length) s = strength, measured in "loop gaps" (s = 1 moves by one gap length) ‖d_S‖ = length of S's own loop gap, used for every method so they push equally hard d̂ = S's own direction, L's mapped direction, or a random direction (control)

9Fold: steering is already a weight edit

Idea. Adding the same vector to every token after layer ℓ is exactly what a bias in that layer's last matrix does. So steering can be written into the weights.

block output: h_out = h + Attn(h) + W_down · a (a = MLP neuron activations) steering: h_out = h + Attn(h) + W_down · a + c (c = −s‖d_S‖d̂) fold: give W_down a bias b = c → identical arithmetic

We checked it: steering and the folded model differ by 1.4×10⁻⁴, which is bf16 rounding. This shows the line between "activation steering" and "weight editing" is thin. A constant push is a bias edit. Section 12 shows the next step up: a push that switches on only when needed.

10Error bars on rates: Wilson interval and z-test

Idea. "21% looped" from 200 problems is uncertain. How wide is the uncertainty, and is 21% vs 10% a real difference?

Wilson 95% interval

p̂ = observed rate, n = trials, z = 1.96 centre = (p̂ + z²/2n) / (1 + z²/n) half = z·√( p̂(1−p̂)/n + z²/4n² ) / (1 + z²/n) interval = centre ± half

Wilson is preferred over the textbook p̂ ± 1.96√(p̂(1−p̂)/n) because it behaves well near 0% and 100%, and its interval is never negative.

Two-proportion z-test

Because all methods use the same 200 problems, a paired test (McNemar) would be sharper, but we didn't save per-problem outcomes. The unpaired test is conservative: if anything it understates the significance.

Part 4 · Weight-space tests

11Block transplant

11.1 · The loss we measure: NLL

Idea. Score a model by how much probability it gives to the actual next token. Negative log likelihood averages −ln(p) over every token in held-out text. Lower is better.

NLL = − (1/N) Σ ln p(true next token) toy: if the model gives the true token p = 0.5, 0.8, 0.25: NLL = −(ln 0.5 + ln 0.8 + ln 0.25)/3 = (0.693 + 0.223 + 1.386)/3 = 0.767 reading it back: e^(−NLL) is the "typical" probability of the right token intact Qwen-0.5B: NLL 0.4075 → e^−0.4075 ≈ 0.67 block 6 deleted: NLL 0.5871 → e^−0.5871 ≈ 0.56

11.2 · The transplant pipeline

S's state entering block s ──A──▶ L's coordinates ──L's block l (L's weights, untouched)──▶ ──B──▶ back to S A = ridge map S_in → L_in fitted on natural states of both models B = ridge map L_out → S_out "pure": fitted on natural states "fit": refitted on what L's block actually outputs when fed A(S_in)

Controls: skip (delete the block: output = input), linear (a ridge map S_in → S_out built from S's own data, no L at all), and random (a random-weight block with the same architecture as L, output map refitted).

11.3 · The recovery score

recovered = (NLL_skip − NLL_replacement) / (NLL_skip − NLL_intact) 0% = as bad as deleting the block, 100% = as good as S's own block, negative = worse than deleting block 6: intact 0.4075, skip 0.5871 → damage = 0.1796 linear stand-in NLL 0.4785 (0.5871 − 0.4785)/0.1796 = +60.5% L's block, pure maps NLL 0.6045 (0.5871 − 0.6045)/0.1796 = −9.7% L's block, B refit NLL 0.5104 = +42.7% random block, B refit NLL 0.5177 = +38.6%

Why the pure transplant fails

A only captures about 60% of L's input (validation R² 0.60–0.64). L's block is nonlinear, so the 40% it gets wrong is not a small blur. It pushes the block into input regions it never saw during training, and the output errors grow. At blocks 12 and 18 the pure transplant scores −283% and −341%. Refitting B mostly learns to undo L's block: a random block does almost as well, and S's own linear stand-in beats both.

A subtle point: at block 6 the pure transplant's output matches S's true output better than deleting the block does (R² 0.77 vs 0.63), yet its loss is worse. Raw R² treats all errors equally, but the model is very sensitive to errors in a few directions. That's why we judge by loss, not by R².

12The rank-1 edit: steering that switches itself on

Idea. Change one MLP output matrix so that the layer adds the anti-loop push only on tokens that look like looping.

An MLP layer ends with out = W_down · a, where a holds the neuron activations (1,536 numbers in SmolLM2-135M) and W_down is 576 × 1,536. Add a rank-1 change (here a is a column vector, as in the code):

ΔW = δ · u vᵀ u: a direction in the residual stream (576 numbers) → "what to add" v: a weight per neuron (1,536 numbers, mostly 0) → "when to add it" new output = W_down·a + δ · u · (v·a) └── t = v·a, one number per token: the trigger

We choose v so that t ≈ −1 on looping tokens and t ≈ 0 on productive ones, and set u = d̂ (the loop direction) and δ = s‖d_S‖. Then:

looping token: t ≈ −1 → adds −s‖d_S‖d̂ (exactly the steering push) productive token: t ≈ 0 → adds nothing

Only the columns j where v_j ≠ 0 change. With 8 nonzero entries that is 8 × 576 = 4,608 weights out of 885k in that matrix.

13The linear program that finds v

Idea. Find the smallest, sparsest neuron weighting v that fires strongly on every looping token and stays quiet on every productive token.

minimise Σⱼ |vⱼ| + λ Σₜ slackₜ subject to v·aₜ ≤ −1 + slackₜ for each looping token t (fire) |v·aₜ| ≤ ε + slackₜ for each productive token t (stay quiet) slackₜ ≥ 0 ε = 0.1, λ = 1 (slack lets a few hopeless tokens break the rule, at a price)

Every piece is linear, so this is a linear program. Solvers such as HiGHS find the exact optimum in seconds. The |vⱼ| is made linear by splitting vⱼ = vⱼ⁺ − vⱼ⁻ with both parts ≥ 0. The two-sided rule |x| ≤ ε becomes two one-sided rules, x ≤ ε and −x ≤ ε.

Toy problem, solved

Four neurons, three looping tokens and three productive tokens. Neuron 1 is clearly a "loop neuron". Neuron 2 also leans toward loops, but less cleanly.

The solver (scipy's HiGHS, run on exactly these numbers) returns v = [−0.5, 0, 0, 0], objective 0.5, no slack needed. The last column checks every constraint. Why not also use neuron 2? Try v = [−⅓, −⅓, 0, 0]: it still fires on loops, but it costs ⅔ > ½ and gives −0.17 on the first productive token, breaking the |t| ≤ 0.1 rule.

Why |v| (L1) gives sparse answers

The full recipe in our runs

  1. Pre-screen. Keep the 1,000 neurons whose loop-vs-productive gap is largest relative to their spread (|mean_loop − mean_prod| / std), so the LP stays small.
  2. Solve the LP on 400 looping and 400 productive tokens.
  3. Keep 8. Score each neuron by how much it actually moves t, |vⱼ| · std(aⱼ), and keep the top 8.
  4. Re-solve the LP with only those 8 neurons allowed.

14AUC: is the trigger any good on new tokens?

Idea. Pick one random looping token and one random productive token. AUC is the chance that the trigger ranks the looping one as more "loopy" (more negative t). 0.5 is a coin flip; 1 is perfect.

toy trigger values looping: −1.2, −0.9, −0.2 productive: 0.0, −0.3, 0.1 count the 3×3 = 9 pairs where looping < productive: −1.2 beats all 3, −0.9 beats all 3, −0.2 beats 0.0 and 0.1 but not −0.3 AUC = 8 / 9 ≈ 0.89

In our runs (held-out tokens)

S's own trigger 0.72 · L's trigger inside L 0.77 · L's trigger ported into S 0.61 · random 8 neurons 0.57.

15Porting the edit from L to S

Idea. L has its own edit (u_L, v_L). Carry both halves into S without using any of S's loop labels.

payload: u_{L→S} = d_L W (section 8.2: a direction goes through the map) trigger: L's trigger value at each aligned token: yₜ = v_L · aₜᴸ find 8 S neurons that reproduce it: minimise Σ|cⱼ| + λ Σ slack subject to |c·aₜˢ − yₜ| ≤ ε + slackₜ for every token

This "port LP" is the same machine as section 13, but now the target is L's trigger value instead of a loop label. Then we measure fidelity: how much of L's trigger the 8 S neurons explain on held-out tokens.

port fidelity R² = 0.045 → S's neurons capture 4.5% of L's trigger compare: the residual-stream map R² ≈ 0.66

Why the two numbers differ so much

The residual stream is the shared "language" every block reads and writes, so it lines up across models. MLP neurons are private wiring: each model learned its own basis, and nothing forces neuron 4,211 of L to have a twin in S. The hybrid edit uses S's own trigger (found with S's own labels) with L's mapped direction. It cut loops from 21% to 14%, about 55% of what S's own edit achieved (21% → 8.5%).

16Picking the strength without cheating

Idea. Choose s on separate problems, then report on the test problems once.

tuning slice (60 problems), s ∈ {2, 4, 8, 16}: coherence check: Qwen-1.5B scores the first 48 generated tokens (early NLL) rule: lowest loop rate whose early NLL ≤ 1.15 × the unedited model's s=2 loops 18.3% s=4 loops 8.3% early NLL 1.51 ✓ chosen s=8 loops 6.7% early NLL 2.41 ✗ (fewer loops, but gibberish) s=16 loops 40% (breaks the model) then on the 200 test problems, once, with s = 4.

Without the coherence rule you could "cure" loops by pushing so hard the model writes nonsense, which also doesn't repeat itself.
